## Overview

A globally distributed, highly available key-value storage system built using the Actor Model,
designed to back a multiplayer online game where players and state are spread across geographic
regions.

## Problem

A multiplayer game backend needs to serve reads and writes fast wherever a player connects from,
while staying available even when individual nodes or regions have trouble. Strong consistency
across geo-distributed replicas would mean paying cross-region round trips on every write, so the
system instead has to reason carefully about *how much* consistency it can give up, and where.

## What I built

- A **key-value store** organized around the **Actor Model**, where each actor owns a slice of
  state and communicates with others only via message passing / RPC.
- **Geo-distributed replication** across regions, keeping reads and writes local to the nearest
  replica rather than routing through a single central store.
- **Eventual consistency** with **last-writer-wins** conflict resolution between replicas that
  diverge before syncing.
- Integration as the backing store for a **multiplayer game backend**, where low read/write
  latency matters more than immediate cross-region consistency.

## Results

- A working, geo-distributed KV store that serves a multiplayer game backend with local read/write
  latency and eventual convergence across regions.
