## Overview

An open-source contribution to Hugging Face's `transformers` generation stack, adding suffix-based
speculative decoding: a proposer that speeds up autoregressive generation without needing a
separate draft model, by reusing repeated patterns already present in the context. I also designed
a unified verification interface so that both suffix-based and tree-based speculative candidates
can be checked in a single target-model forward pass.

## Problem

Speculative decoding speeds up LLM inference by having a cheap "proposer" guess several tokens
ahead, which the expensive target model then verifies in parallel. The standard approach needs a
separate draft model, which adds memory and engineering overhead. Many real workloads — code in
particular — contain a lot of repeated structure (variable names, boilerplate, prior context) that
a draft-model-free proposer can exploit directly. Separately, the generation stack needed a single
verification path that could handle both this new suffix-based proposal shape and the existing
tree-based speculative decoding shape, instead of duplicating verification logic per method.

## What I built

- A **draft-model-free suffix proposer** that reuses repeated context patterns to propose
  candidate continuations, integrated into the Hugging Face `transformers` generation stack.
- A **unified verification interface** that lets both suffix-based and tree-based speculative
  candidates be verified together, so multiple candidate continuations can be checked in a
  **single target-model forward pass**.

## Results

- **1.74x** decoding speedup on WildChat code-suffix workloads using the suffix-based proposer.
- **1.30x** speedup on SWE-bench tree-spec workloads via the unified verification interface.

## Trade-offs & limitations

- Suffix-based speculation benefits most from workloads with repeated structure (e.g. code); gains
  on less repetitive natural-language generation would likely be smaller.
