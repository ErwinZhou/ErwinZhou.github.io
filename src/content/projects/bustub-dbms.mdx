## Overview

BusTub is a teaching DBMS used in CMU's database systems course. Over the semester I implemented
its performance-critical internals in C++: a disk-oriented buffer pool manager, B+ tree indexing,
a transaction-aware query execution engine, and rule-based optimizations.

## Problem

A database has to serve correct results *and* stay fast as data outgrows memory. That means
careful page management, concurrency control without data races, and an optimizer that rewrites
query plans into cheaper equivalents.

## Architecture

```
SQL → Binder → Planner → Optimizer (rewrite rules) → Execution engine
                                                          │
                          Buffer Pool Manager ◄───────────┘
                                   │
```

## What I built

- A **disk-oriented buffer pool manager** with page eviction and pin/unpin semantics.
- **B+ tree indexing** supporting point and range lookups under concurrent access.
- A **query execution engine** with both transaction-level and batch (vectorized) operators.
- **5+ optimizer rewrite rules**: filter–scan merging, SeqScan/OrderBy → IndexScan selection,
  NestedLoopJoin → HashJoin, and Sort–Limit → TopN.
- Performance operators: **external merge sort**, window functions, and a **GRACE hash join** with
  disk-backed intermediate pages.

## Results

- **+56%** benchmark performance from the optimizer and operator work.
- Ranked in the **top 5%** of the course leaderboard.

## Trade-offs & limitations

- Optimizer rules are heuristic, not cost-based — great wins on the benchmark shapes, but a true
  cost model would generalize better.
