## Overview

A high-performance FP16 GEMM (general matrix multiply) kernel for NVIDIA Blackwell (SM100) GPUs,
written using TVM/TIRX. I started from a minimal single-tile kernel and incrementally added
optimization stages — tensor core usage, asynchronous memory movement, pipelining, and warp
specialization — until the kernel's structure converged toward what production libraries like
cuBLAS and CUTLASS do.

## Problem

GEMM is the workhorse operation of deep learning, and modern GPUs dedicate specialized hardware
(tensor cores, async copy engines, dedicated on-chip memory) to it. Getting anywhere close to
peak throughput means orchestrating that hardware correctly: keeping tensor cores fed without
stalling on memory, overlapping data movement with compute, and coordinating many warps and
thread blocks without race conditions — none of which a naive tiled kernel does for you.

## What I built

- A **single-tile FP16 GEMM kernel** in TVM/TIRX as the correctness baseline.
- Incremental integration of **Blackwell (SM100) tensor cores (tcgen05)** for the core matmul.
- **TMA-based asynchronous data movement** from global to shared memory, overlapped with compute.
- Use of **Tensor Memory (TMEM)** and **mbarriers** for fine-grained cross-warp synchronization.
- **Software pipelining** and **CTA clusters** to keep multiple tiles in flight simultaneously.
- **Warp specialization**, splitting warps into producer/consumer roles to further hide latency.

## Results

- Progressed a naive single-tile kernel through multiple optimization stages to a structure
  matching production-grade (cuBLAS/CUTLASS-style) FP16 GEMM implementations on Blackwell SM100.

## Trade-offs & limitations

- Targets FP16 GEMM specifically on SM100; the same staged approach would need rework for other
  precisions (FP8, BF16) or older architectures without tcgen05/TMA.
